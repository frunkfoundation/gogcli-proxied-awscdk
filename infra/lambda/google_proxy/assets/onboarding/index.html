Prepare the shared Google application

One External application can connect personal Gmail and different Workspace organizations. An organization's administrator may restrict it.

1. Enable the selected APIs

Project: use the selected project above for every Console step.

Open each service you selected. Keep it enabled if the Console shows “Manage”; otherwise choose “Enable”.

2. Review audience, branding, and permissions

Open Branding ↗. Supply these fields when setting up the application; keep existing names and monitored contact emails when already configured.

  • User support email: select jay.jakosky@gmail.com if offered in the dropdown, or another eligible email you monitor.
  • Developer contact information / Contact Information email: jay.jakosky@gmail.com is an acceptable monitored contact.

If Google shows Get started, use these name and contact values and choose External in the initial setup. At Finish, review the Google API Services: User Data Policy, select “I agree” if you agree, then choose Create.

If Google asks for Authorized domains, use k-rae.com for this callback. Keep existing homepage, privacy policy, terms, and logo settings; follow any requirements Google actually presents.

Open Audience ↗ and review these settings:

  • User type / Audience: External.
  • Publishing status: In production for durable use. Choose Publish app if the status is Testing.
  • Test users (only while Testing): add each account you intend to authorize. Saved accounts: . Testing grants can expire after seven days.

Open Data Access ↗. Under Add or remove scopes, select these requested permissions and save:

    Identity permissions identify the Google account. Google consent and access for your tools are separate. Publishing does not complete Google's verification; follow any actual Google or administrator requirement.

    3. Prepare a Web client and register its callback

    Open Clients ↗. Open an existing Web client or choose Create client, then supply these fields. Keep an existing client's name; this suggestion is for a new client.

    Application type: Web application.

    Authorized JavaScript origins (optional): leave blank for a new client; this application uses server redirects. Keep existing entries when reusing a client.

    Choose Create for a new client or Save for an existing client, then download the Web client's JSON. A previous Desktop client served local software and cannot supply this hosted callback.

    4. Save your reviewed settings for this client

    These are your confirmations, not an independent check of Google Console. Importing another client requires review again.

    Administrator instructions for a Google policy block

    Advanced: use the CLI

    Build this repository with make build. Configure the proxy endpoint, authorized AWS profile, and owner-provided API key in your gog configuration. Google credentials stay on the server.

    Run bin/gog auth doctor --check for bounded Gmail and Drive reads as your actual caller. A server check establishes only that verifier's access.
